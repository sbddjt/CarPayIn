## 출차 및 결제 시나리오 전체 흐름 (최종)

### 시동 ON 및 주차 상태 감지

사용자가 차량에 탑승해서 시동을 켜는 순간 백그라운드 서비스가 VHAL의 `IGNITION_STATE` 속성을 감지해서 자동으로 깨어납니다. 서비스는 백엔드를 찌르기 전에 EncryptedSharedPreferences의 로컬 플래그를 먼저 확인합니다. `parked: false`면 주차 중이 아니니 아무것도 하지 않습니다. `parked: true`면 저장된 lot_id와 session_id를 들고 백엔드에 현재 요금 조회를 요청합니다. 이 과정에서 전체 차량이 백엔드를 찌르는 게 아니라 입차 알림을 받아서 로컬 플래그가 기록된 차량만 통신하기 때문에 불필요한 트래픽이 발생하지 않습니다.

### 요금 조회

백엔드는 앱의 요청을 받으면 아이파킹에 해당 번호판의 현재 주차 요금을 조회합니다. 아이파킹은 입차 시각부터 현재까지의 주차 시간에 해당 주차장 요금 정책을 적용해서 최종 청구 금액을 계산하고 백엔드로 반환합니다. 백엔드는 이 금액을 앱으로 전달합니다. 요금 조회 시 Redis를 먼저 확인하고 미스가 발생하면 PostgreSQL에서 파킹 세션을 조회합니다. 장기 주차로 Redis 세션이 만료된 경우에도 PostgreSQL이 source of truth이기 때문에 문제없이 처리됩니다.

### 정산 확인 UI 표시

앱이 요금 정보를 받으면 인포테인먼트 화면에 정산 확인 화면을 띄웁니다. 주차장 이름, 주차 시간, 청구 금액이 표시되고 예와 취소 버튼이 제공됩니다. 비밀번호나 PIN 입력은 없습니다. VIN 기반 차량 인증과 시동을 켠 행위 자체가 본인 확인 수단이 됩니다. 사용자는 금액을 확인하고 예를 한 번 탭합니다.

### 결제 처리

예를 탭하는 순간 앱이 백엔드에 결제 처리를 요청합니다. 앱은 결제와 관련된 어떠한 키도 갖고 있지 않습니다. 백엔드는 VIN으로 DB에서 customer_key를 직접 조회하고, 이중 결제 방지를 위해 session_id, 번호판, 청구 금액, 밀리초 단위 timestamp를 조합한 idempotency_key를 생성합니다. 이 키와 함께 customer_key, 청구 금액을 Mock PG 서버에 전달합니다. Mock PG는 idempotency_key를 먼저 확인해서 이미 처리한 요청이면 즉시 무시합니다. 처음 들어온 요청이면 customer_key로 billing_key를 조회하고, billing_key로 카드 원번호를 꺼낸 뒤 VPN 터널을 통해 OpenStack 프라이빗 클라우드의 카드 승인 서비스로 전달합니다. (통신 지연 로직 구현도 필요) 카드 승인 서비스가 승인 처리를 완료하면 승인번호와 거래 ID를 생성해서 Mock PG를 거쳐 백엔드로 반환합니다. (결제 완료 후 3-5초 후 차단기가 열립니다 알림)

### 결제 완료 후처리

백엔드는 승인 결과를 받는 즉시 Kafka 토픽에 결제 완료 이벤트를 발행합니다. 백엔드는 아이파킹에 빠르게 응답하고, Kafka Consumer가 나머지를 비동기로 처리합니다. Consumer는 순차적으로 PostgreSQL 거래 내역 테이블에 승인 결과를 기록하고, 파킹 세션 status를 completed로 업데이트하고, 아이파킹에 해당 번호판의 status를 paid로 전달합니다. 이 세 가지 처리 중 하나가 실패해도 Kafka에 메시지가 남아있기 때문에 재처리가 가능하고 데이터 유실이 발생하지 않습니다.

앱의 로컬 플래그는 `parked: false`로 초기화되고 인포테인먼트 화면에 결제 완료 메시지와 전자영수증 정보가 표시됩니다.

### 출구 차단기 개방

차량이 출구에 진입하면 LPR이 번호판을 인식합니다. 아이파킹 PMS는 자기 DB에서 해당 번호판의 status를 확인합니다. paid면 백엔드와 별도 통신 없이 즉시 차단기를 열어줍니다. 사용자는 멈추지 않고 그냥 나갑니다.

### 예외 처리

결제가 실패하면 인포테인먼트 화면에 실패 안내와 함께 다른 결제수단 선택 옵션이 표시됩니다. paid 상태가 아이파킹에 전달되지 않은 상태에서 출구에 진입하면 차단기가 열리지 않고 현장 무인정산기로 안내됩니다. Kafka Consumer 처리 중 아이파킹 paid 전달이 실패하면 Consumer가 재시도해서 결국 전달을 보장합니다.

```
시동 ON → IGNITION_STATE 감지
    ↓
로컬 플래그: parked: true 확인
    ↓
앱 → 백엔드: 요금 조회
백엔드 → 아이파킹: 현재 요금 조회
아이파킹 → 백엔드: ₩6,000 반환
    ↓
인포테인먼트:
"강남 아이파킹 | 3시간 20분 | ₩6,000
 정산하시겠습니까? [예] [취소]"
    ↓ 예 클릭 1회
앱 → 백엔드: 결제 요청
백엔드: DB에서 customer_key 조회
idempotency_key 생성
    ↓
[Mock PG - 퍼블릭]
idempotency_key 중복 확인
    ↓ VPN
[OpenStack 카드 승인]
승인번호 + 거래 ID 발급
    ↓
백엔드 → Kafka 토픽 publish
    ↓
Kafka Consumer:
  → PostgreSQL: 거래 내역 저장 + 세션 completed
  → 아이파킹: status = paid 전달
로컬 플래그: parked = false
    ↓
인포테인먼트: "결제 완료 | 출차하세요"
    ↓
출구 LPR → paid 확인 → 차단기 즉시 개방
```
