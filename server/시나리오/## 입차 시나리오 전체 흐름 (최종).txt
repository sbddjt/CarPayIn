## 입차 시나리오 전체 흐름 (최종)

### 백그라운드 서비스 자동 시작

사용자가 차량에 탑승해서 시동을 켜는 순간 백그라운드 서비스가 VHAL의 `IGNITION_STATE` 속성을 감지해서 자동으로 깨어납니다. 사용자는 아무것도 하지 않습니다. 서비스가 시작되면 NaviHelper SDK에 목적지 변경 콜백을 등록하고, Fused Location SDK에 지오펜스를 등록합니다. 이때 지오펜스 반경은 고정값이 아니라 VHAL의 차량 속도를 실시간으로 읽어서 동적으로 설정합니다. 시속 30km 이하면 300m, 30~60km면 600m, 60km 이상이면 1km로 반경을 넓힙니다. 속도가 빠를수록 반경을 넓혀서 네트워크 지연이 발생해도 차량이 차단기에 도착하기 전에 사전 등록이 반드시 완료되도록 보장합니다. 지오펜스 좌표 목록은 앱 초기 실행 시 백엔드에서 내려받아 로컬에 캐싱해둔 제휴 주차장 목록을 사용합니다.

### 사전 알림 트리거

사용자가 내비게이션을 켜고 목적지를 제휴 주차장으로 설정하거나, 운전 중 동적으로 계산된 지오펜스 반경 안으로 진입하면 백그라운드 서비스가 이를 감지합니다. 둘 중 하나라도 조건이 충족되면 서비스가 UI 없이 백엔드로 사전 알림 요청을 자동으로 전송합니다. 요청에는 VIN, 번호판, 주차장 ID, 트리거 종류가 포함됩니다.

백엔드는 사전 알림을 수신하면 Redis에 해당 번호판과 주차장 ID 조합으로 incoming 상태를 TTL 1시간으로 기록하고, 아이파킹 B2B API를 호출해서 해당 주차장 PMS에 번호판을 사전 등록합니다. 아이파킹 PMS는 이 시점부터 해당 번호판이 입차하면 백엔드로 이벤트를 보내야 한다는 걸 알고 있게 됩니다.

### 입차 및 차단기 개방

차량이 주차장 입구에 진입하면 LPR 카메라가 번호판을 인식합니다. 아이파킹 PMS는 모든 차량에 대해 검증 없이 즉시 차단기를 열어줍니다. 클라우드 응답을 기다리지 않고 현장에서 바로 처리하기 때문에 지연이 없습니다. 차단기 개방 이후 PMS는 해당 번호판이 사전 등록된 차량인지 자기 DB에서 확인합니다. 사전 등록된 번호판이면 고유한 event_id, 번호판, 주차장 ID, 밀리초 단위 timestamp를 포함한 입차 이벤트를 백엔드로 전송합니다. 사전 등록이 없는 일반 차량이면 차단기만 열고 끝이며 백엔드로 아무것도 보내지 않습니다.

### 파킹 세션 생성

백엔드가 입차 이벤트를 수신하면 직접 Redis와 PostgreSQL에 쓰지 않고 먼저 Kafka 토픽에 메시지를 발행합니다. 백엔드는 즉시 아이파킹에 수신 완료 응답을 반환합니다. 이후 Kafka Consumer가 메시지를 읽어서 Redis에 파킹 세션을 캐싱하고 PostgreSQL에 파킹 세션을 영구 저장합니다. 두 저장이 순차적으로 처리되기 때문에 백엔드가 중간에 죽어도 Kafka에 메시지가 남아있어서 데이터가 유실되지 않습니다. PostgreSQL이 source of truth이며 Redis는 빠른 조회를 위한 캐시입니다. 장기 주차로 Redis 세션이 만료되더라도 출차 시 PostgreSQL에서 조회하면 됩니다.

멱등성 처리는 event_id, 번호판, 주차장 ID, timestamp 조합을 키로 사용합니다. 네트워크 재시도로 동일한 이벤트가 중복으로 들어오면 이 키로 감지해서 무시합니다. 단순히 번호판과 주차장 ID만으로 키를 잡으면 잠깐 나갔다 다시 들어오는 재입차가 중복으로 처리될 수 있기 때문에 밀리초 단위 timestamp를 반드시 포함합니다.

### 입차 확정 알림 및 로컬 플래그 저장

Kafka Consumer가 세션 저장을 완료하면 백엔드가 AAOS 앱으로 입차 확정 푸시 알림을 전송합니다. 앱이 알림을 수신하는 순간 인포테인먼트 화면에 입차 확인 메시지를 표시하는 동시에 EncryptedSharedPreferences에 로컬 플래그를 즉시 기록합니다. (redis 재시도 로직 추가) 여기에는 parked: true, lot_id, session_id가 저장됩니다. 이 로컬 플래그가 나중에 시동을 켤 때 백엔드를 찌를지 말지 판단하는 기준이 됩니다. 앱을 열고 있지 않아도 백그라운드 서비스가 알림을 수신해서 플래그를 저장합니다. 백그라운드 서비스는 이 시점부터 주차 경과 시간과 예상 요금을 화면에 실시간으로 표시하기 시작합니다.

### 예외 처리

아이파킹 PMS와 백엔드 간 통신이 끊기면 PMS는 입차 이벤트를 SQLite 로컬 큐에 저장합니다. 재연결 시 큐에 쌓인 이벤트를 순서대로 재전송하고 백엔드는 멱등성 키로 중복을 필터링합니다. 사전 알림 TTL이 만료되기 전에 실제 입차가 오지 않으면 Redis와 아이파킹 PMS에서 해당 번호판 정보가 자동으로 삭제됩니다.

---

```
시동 ON → IGNITION_STATE 감지
    ↓
백그라운드 서비스 실행
NaviHelper 리스너 등록
Fused Location 동적 지오펜스 등록
  (차량 속도 → 반경 300m~1km 자동 조정)
    ↓ 목적지 설정 or 반경 진입
사전 알림 → 퍼블릭 백엔드
    ↓
Redis: incoming (TTL 1시간)
아이파킹 PMS: 번호판 사전 등록
    ↓
LPR 인식 → 모든 차량 차단기 즉시 개방
    ↓ 사전 등록 차량만
백엔드 → Kafka 토픽 publish
    ↓
Kafka Consumer:
  → Redis: 파킹 세션 캐싱
  → PostgreSQL: 파킹 세션 영구 저장
    ↓
AAOS 앱: 입차 확정 알림 수신
  → 인포테인먼트 화면 표시
  → EncryptedSharedPreferences:
     parked: true / lot_id / session_id 저장
```
